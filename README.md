# Crypto_Couples

Visual cryptography in pure Python — no third-party dependencies.

Split secrets into shares (images, audio, video, arbitrary files). Reconstruct
them by stacking transparencies, XORing, or Lagrange interpolation over GF(2⁸).
Available as a **CLI tool**, a **FastAPI backend**, or a **self-hosted PWA**.

---

## Architecture

```
┌─────────────────────────────────────────────────────┐
│  Browser (PWA)                                      │
│  Vite + React + Tailwind                            │
│  Calls REST + WebSocket (JSON)                      │
└──────────────────────┬──────────────────────────────┘
                       │  VITE_API_URL / VITE_WS_URL
                       ▼
┌─────────────────────────────────────────────────────┐
│  FastAPI backend  (uvicorn)                         │
│  Adapters import crypto_couples / crypto_media      │
│  directly — no subprocess, no REST bridge.          │
│  Temp files lifecycle-managed, ops cleaned by TTL.  │
└──────────────────────┬──────────────────────────────┘
                       │  import crypto_couples
                       ▼
┌─────────────────────────────────────────────────────┐
│  crypto_couples.py  /  crypto_media.py              │
│  Pure stdlib. 1-bit visual crypto, Shamir over      │
│  GF(2⁸), audio/video splitting.                     │
└─────────────────────────────────────────────────────┘
```

## Quick start — CLI

```bash
# Split into 2 stacking shares
python3 crypto_couples.py demo message.png --text 'SECRET' --scale 6
python3 crypto_couples.py split message.png --shares 2 --method stack --seed 42 --out share

# Reveal (physically stack transparencies, or digitally):
python3 crypto_couples.py reveal share.1.png share.2.png --method stack --out revealed.png
```

See `python3 crypto_couples.py -h` and `python3 crypto_media.py -h` for all options.

## Quick start — PWA (development)

```bash
# Terminal 1: Backend
cp .env.example .env          # edit as needed
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000

# Terminal 2: Frontend
cd frontend
npm install
npm run dev                   # → http://localhost:5173
```

Paste the contents of `frontend/.env.example` into `frontend/.env` if your
backend is not at the default address.

## Environment variables

### Backend

| Variable | Default | Description |
|---|---|---|
| `APP_ENV` | `development` | `development` · `test` · `production` |
| `HOST` | `127.0.0.1` | Bind address |
| `PORT` | `8000` | Listen port |
| `FRONTEND_ORIGIN` | `http://localhost:5173` | CORS origin (exact match; no `*`) |
| `MAX_UPLOAD_SIZE` | `536870912` | Max upload bytes (default 512 MB) |
| `TEMP_DIRECTORY` | `./backend/data/ops` | Working dir for temp uploads / shares |
| `OP_TTL_SECONDS` | `3600` | How long temp files live (default 1 h) |
| `FFMPEG_PATH` | `ffmpeg` (on `$PATH`) | Override ffmpeg binary location |

`HISTORY_PATH` is hard-coded to `backend/data/history.db` (SQLite). The
directory is created on first write.

### Frontend

| Variable | Default | Description |
|---|---|---|
| `VITE_API_URL` | `/api` | REST base URL (absolute or relative) |
| `VITE_WS_URL` | auto-derived from `location.host` | WebSocket base URL (use explicit `ws://…` in dev) |

Both are baked into the bundle at build time (`import.meta.env`).

## Production build & deploy

### Self-hosted (full fidelity)

```bash
# Backend — single entrypoint, no build step
APP_ENV=production uvicorn app.main:app --host 0.0.0.0 --port 8000

# Frontend — static output in frontend/dist/
cd frontend && npm run build   # or: node ./node_modules/typescript/bin/tsc --noEmit && npx vite build
# Serve dist/ from any static host (Nginx, Cloudflare Pages, etc.)
# Point VITE_API_URL / VITE_WS_URL at the live backend.
```

The service worker (Workbox) precaches the app shell for offline use. It is
generated by `vite-plugin-pwa` during `vite build`. The build must complete
on a full Linux runner (GitHub Actions `ubuntu-latest` works; Termux ARM
may OOM on SW minification).

### Vercel (serverless)

`vercel.json` builds the SPA with `@vercel/static-build` and runs the FastAPI
backend as a Python function (`api/index.py`), serving both from the same
origin so the PWA uses relative `/api` URLs. WebSocket events are unavailable
there — the SPA degrades to REST detail polling automatically, and secrets
are processed server-side in ephemeral `/tmp` (operations and history are not
persistent across cold instances, and request bodies are platform-capped, so
video splits belong on the self-hosted deployment).

```bash
vercel deploy --prod   # works logged-out as a temporary deploy; claim it in the dashboard
```

Optional Vercel env vars (defaults are set in `api/index.py`):

| Variable | Default (serverless) | Purpose |
|---|---|---|
| `APP_ENV` | `production` | Env mode |
| `TEMP_DIRECTORY` | `/tmp/crypto_couples/ops` | Ephemeral working dir |
| `HISTORY_PATH` | `/tmp/crypto_couples/history.db` | Ephemeral history |
| `OP_TTL_SECONDS` | `3600` | Ephemeral op lifetime |

### Reverse proxy (Nginx, Caddy)

Backend must receive `/api/` paths. Frontend static files get `/`. CORS
(`FRONTEND_ORIGIN`) must match the exact browser origin including protocol.

## Testing

All three layers run independently and in CI.

```bash
# Core engine — stdlib only, no deps
python3 -m pytest tests/ -q

# Backend — FastAPI, httpx, websockets
cd backend && pip install -r requirements.txt
APP_ENV=test python3 -m pytest tests/ -q

# Frontend — Vitest + TypeScript
cd frontend && npm install
npx tsc --noEmit && npx vitest run

# E2E smoke — starts a live server, exercises real HTTP + WS paths
PYTHONPATH=. python3 backend/scripts/smoke_e2e.py
```

### CI (GitHub Actions)

Every push to `main` and every pull request runs:

1. **Core + backend** job: `pytest` on `tests/` and `backend/tests/`, then a
   live E2E smoke (`smoke_e2e.py`) that exercises image/file split-reveal,
   WS progress streaming, download-all, and history.
2. **Frontend** job: `tsc --noEmit`, `vitest run`, `vite build` (verifies
   Workbox SW generation), and PWA artifact checks (`dist/sw.js`,
   `dist/manifest.webmanifest`).

See `.github/workflows/ci.yml`.

## Security & limitations

- **Crypto toy.** Protects against casual sharing; does not withstand an
  adversary with all-but-one shares against a weak image.
- **Mersenne Twister.** Python's `random` is not cryptographically secure.
  Use `secrets` + a vetted library for real secrets.
- **No content on the server.** Files are uploaded, split, and deleted within
  the same request cycle. History stores only metadata (names, sizes, checksums,
  operation kinds).
- **Backend is self-hosted.** The official deployment is a single-process
  `uvicorn` instance. No external data services, no analytics, no phone-home.
- **1-bit visual crypto.** Image reconstruction produces a binarized (B/W)
  image — this is by design, not a limitation. Byte-identical roundtrip is
  guaranteed only for file and audio paths.
